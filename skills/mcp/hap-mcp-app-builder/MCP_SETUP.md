# HAP MCP 接入与异常恢复指南

仅在未检测到可用 HAP MCP 服务、令牌鉴权不通、工具数量不全（`tools_count < 170`）或应用级权限受阻时读取。配置或修复完成后返回 [入口公共前置检查](SKILL.md#公共前置检查与智能目标定位) 继续原任务。

---

## 场景一：未检测到任何 HAP MCP 服务（`0 个`）

当运行时环境中未检测到任何明道云（HAP）MCP 服务时，不再要求用户手动查找 URL 或手写 JSON，直接引导用户通过明道云平台的 **「连接 AI」** 入口一键复制安装提示词：

```markdown
🔌 **未检测到明道云（HAP）MCP 服务连接**
请在明道云平台打开 **「连接 AI」** 弹窗完成配置：
1. 在「安装能力」中勾选 **「HAP 应用助手」**；
2. 在下方选择或点击 **「创建个人访问令牌」**（需开启所有应用与所有接口权限）；
3. 点击底部 **「复制提示词（发送给 Agent 安装）」**，直接粘贴到当前对话发送给我即可。
```

### Agent 接手执行规则（跳过 Skill 重复安装）
- 由于用户已处于本 `hap-mcp-app-builder`（HAP 应用助手）会话中，收到用户粘贴的「连接 AI」安装提示词后，**必须自动跳过 HAP 应用助手 Skill 的下载与安装步骤**；
- 仅从提示词中提取 **MCP 服务地址（URL）** 与 **个人访问令牌（`Authorization: Bearer <pat_token>`）**，协助写入当前宿主的 MCP 配置文件（增量添加或更新目标 MCP 条目，完整保留用户原有的其他 MCP 服务）；
- 写入配置后，提醒用户：**“若工具列表未自动加载，请在 AI 工具的 MCP 设置中点击刷新/重连（Reload MCP）使其生效”**；
- 严禁在聊天回复、日志、Skill 文件或 Git 仓库中明文回显或持久化真实令牌。

## 场景二：已检测到 HAP MCP 服务，但连通性/鉴权失败（令牌不通）

当检测到 `{MCP_SERVER_NAME}` 服务，但调用全局接口（如 `get_org_list`）返回 `401`、令牌失效或无权限时（注意：若仅单个应用内接口报 `10001 Http Headers verification failed`，属于调用漏传 `appId`，由 Agent 自愈补传，严禁误报为令牌失效），输出以下引导：

```markdown
🔑 **已检测到 `{MCP_SERVER_NAME}` 服务，但个人访问令牌（PAT）已失效或无法通过鉴权**
请在明道云平台打开 **「连接 AI」** 弹窗：
1. 重新选择或点击 **「创建个人访问令牌」** 生成有效令牌；
2. 点击底部 **「复制提示词（发送给 Agent 安装）」**，直接粘贴到当前对话发送给我，我将直接为你更新 `{MCP_SERVER_NAME}` 的令牌配置。
```

### Agent 接手执行规则
- 收到用户发送的「连接 AI」提示词（或新令牌）后，**自动跳过 Skill 安装**，仅原地更新宿主 MCP 配置中 `{MCP_SERVER_NAME}` 的 `url` 与 `Authorization: Bearer <pat_token>`，并提示刷新/重连 MCP 服务。

## 场景三：已检测到 HAP MCP 服务，但工具数量不全（`tools_count < 170`）

当 `MCP_SERVER_NAME` 可用工具数 `tools_count < 170` 时，说明明道云「个人访问令牌」未勾选全部接口范围，输出以下引导并硬性阻断：

```markdown
🚨 **明道云 MCP 工具数量不全（当前可用：{tools_count} / 170）！**
工具缺失会导致应用搭建、门户/打印模板配置、角色与工作流节点修订等环节执行失败。
**开启全部工具步骤**：
1. 在明道云右上角点击 **「个人头像 → 授权与访问 → 个人访问令牌」**；
2. 找到当前使用的令牌，点击右侧 **`···`（编辑）**；
3. 将 **「应用范围」** 设为 **「所有应用」**，在 **「接口范围」** 中勾选 **「所有接口」**，点击 **「确认」** 保存；
4. 保存后在 AI 工具的 MCP 设置中点击 **刷新/重连（Reload MCP）**，再告诉我继续即可。
```

## 场景四：令牌有效且工具齐全，但新建应用或访问目标应用被拒（范围与角色排查）

当 `tools_count >= 170` 且 `get_org_list` 正常，但在调用 `create_app`、`get_app_info(appId)` 或结构修改接口时返回无权限/找不到应用，严禁盲目让用户重装 MCP，应按以下 3 项精准引导用户核查：

1. **令牌「应用范围」受限（选了“指定应用”）**：
   - 引导前往明道云 **「右上角个人头像 → 授权与访问 → 个人访问令牌 → 编辑当前令牌」**，检查 **「应用范围」** 是否被设为了 **「指定应用」**。若需新建应用或操作其他应用，请将其改为 **「所有应用」**（或将目标应用勾选加入指定列表）并保存。
2. **环境或「组织」范围不匹配**：
   - 若用户提供的应用链接所属域名（如沙盒环境、专属私有部署环境）或所属组织不在当前令牌授权的 `organizations` 中，提示用户在对应环境/组织下打开 **「连接 AI」** 复制提示词接入，或在令牌编辑中检查所选 **「组织」**。
3. **明道云账号自身的「角色权限不足」（非令牌配置问题）**：
   - 若确认令牌已开启「所有应用 + 所有接口」且组织一致，则说明是**用户本人的明道云账号权限受限**：
     - **新建应用被拒**：该组织管理员限制了普通成员创建应用，需联系组织管理员开通「创建应用」权限；
     - **修改已有应用被拒**：当前账号在该应用中仅为普通业务成员（非应用的 **「管理员 / 运营者 / 开发者」**），需联系该应用管理员将账号加入管理员或开发者角色。

---

## 连接验证与恢复执行

完成上述任一配置或权限修复并刷新重连 MCP 后，立即返回 [入口公共前置检查](SKILL.md#公共前置检查与智能目标定位)，依次校验：
1. 服务识别；
2. **`tools_count >= 170` 全量工具门禁**；
3. `get_org_list` 或目标 `get_app_info(appId)` 连通性。

全部通过后无缝继续用户原本的搭建、修改或数据操作任务。
