# HAP 图表设计指南

供页面 Build、页面修订与工作表统计图修订共用。按业务问题确定统计口径和图表类型；所属领域的身份、布局、授权、读写及核验规则由对应 Skill 和执行器负责。本指南不增加探查步骤，优先复用有效的上游输入和已知结构。

用户明确的统计和视觉要求优先于默认建议，但须有真实数据依据且在工具能力范围内。局部修改保留未涉及的类型、口径和样式，不因加载选型指南重新设计已有图表。

## 一、统计口径与数据来源

先明确统计对象、聚合方式、维度、筛选、时间范围及数据权限范围，再选择展示方式。

**不能把维度表作为业务事件统计数据源，必须用事实表。**

- **事实表**：借阅记录、订单、工单、销售流水、考勤记录等，每行代表一次业务事件。
- **维度表**：图书分类、商品类目、员工档案、客户档案、部门表等，每行代表一个实体。

正确做法是在事实表上，以分类字段（关联或选项字段）作为维度分组，对事实行计数或求和。

若统计目标本身是客户总数、设备数量等实体存量，应使用对应实体表；不能将实体数量当作订单、借阅等业务事件数量。

| 分析目标 | 正确数据源 | 错误数据源 |
|---|---|---|
| 各分类借阅占比 | 借阅记录表（按分类字段分组） | 图书分类表 |
| 各客户订单量 | 订单表（按客户字段分组） | 客户档案表 |
| 各部门工单数 | 工单表（按部门字段分组） | 部门表 |

- **单图真实同源**：指标和维度必须映射到所选数据源中的真实字段，不编造字段，也不以名称相似代替统计含义。缺少字段或计算依据时报告具体缺口。
- 明确计数、去重计数、求和、平均等聚合含义；比例明确分子与分母，目标达成明确实际值和目标值。日期及地区粒度、排序、排名截取按业务要求确定。
- 时间范围与数据权限范围遵循业务要求，不把工具的默认时间窗口或全量范围当作用户要求；页面筛选器如何联动由页面规范另行处理。
- **动态时间范围**：调用 `create_chart` / `update_chart` 调整图表整体的近 7 天、未来 30 天、本月等范围时，使用顶层 `timeFieldId` + `timeRange`，是否包含今天按业务要求设置 `includeToday`；枚举严格依实时 MCP Schema，例如未来 30 天为 `next30Days`。保留随日期滚动的语义，不换算成执行当天的固定日期区间。
- **日期筛选边界**：日期字段的 `filter.between/notbetween` 使用具体日期值（如 `YYYY-MM-DD`），禁止将 `today`、`next30Day`、`next30Days` 等动态标记放入其 `value`；数值字段的数值区间不受此日期格式限制。仅调整图表整体时间范围时，保留其他业务筛选，不附带清空或重写 `filter`。

## 二、图表选型

先确定业务问题，再核对数据条件与统计口径，最后从适用类型中选择最容易读懂的表达。精确比较分类大小优先柱形图或条形图，不为视觉丰富增加理解负担。用户指定类型时先检查适用条件；不满足时说明缺口和可行替代，不擅自换图或改变统计定义。

沿用 `spec-pages-charts` 的图表说明与设计建议，并按已核实的 MCP 能力补齐新增类型。下表说明“要回答什么问题、需要什么数据、何时适合使用”，保留影响选型的数据结构要求。数量建议是设计推荐，不是接口默认值；参数名、必填项、组合限制和样式取值按所调用工具的实时 Schema 配置。

| 图表类型 (`chartType`) | 适用场景 | 数据与结构要求 | 设计建议与边界 |
|---|---|---|---|
| 数值图（`numberChart`） | KPI 单值汇总指标卡 | 一个汇总指标，如总额、总笔数、均值或达成率 | 明确聚合含义、单位与范围；页面内样式与尺寸由页面规范决定 |
| 柱形图（`columnChart`） | 纵向分类对比 | 分类与数值指标；比较系列时还需明确分组依据 | 看分项构成可用堆叠，看各分类内部占比可用百分比堆叠；系列须具有可比较口径 |
| 条形图（`barChart`） | 横向分类对比 | 分类与数值指标 | 类别较多或名称较长时优先；展示可相加的分项构成时可用堆叠 |
| 对称条形图（`symmetricBarChart`） | 双侧群体或指标对比 | 共用分类，两侧各一个数值指标 | 两侧须有可比较口径与明确单位，不能只为左右对称而拼接无关指标 |
| 折线图（`lineChart`） | 时间趋势 | 时间维度与数值指标，明确时间粒度 | 可采用平滑线展示趋势；需保留突变或离散变化含义时使用普通折线 |
| 雷达图（`radarChart`） | 多指标综合比较 | 对比对象的分类维度，以及少量可比较指标 | 指标单位或量级不同时，先明确可比较的尺度；无可靠依据时不自行归一化或声称综合评分 |
| 散点图（`scatterChart`） | 两个数值变量的关系 | 两个数值指标，以及明确的每个点所代表的对象 | 用于观察分布、相关性与异常点，不把相关性解释为因果关系 |
| 饼图（`pieChart`） | 占比分布 | 同一总体下可比较的分类及其数值，或同口径的多个构成指标 | 建议类别不超过 8 个；类别过多时改用 TopN 或条形图，并说明展示范围 |
| 玫瑰图（`roseChart`） | 放射状分类对比 | 一个主分类和一个指标；需要比较系列时可增加分组 | 用等角扇区半径展示差异；精确比较优先柱形/条形图，不把半径差异当作占比 |
| 矩形树图（`treemapChart`） | 分类数值构成 | 一个分类和一个数值指标 | 用矩形面积观察主要构成；不承诺当前单维度能力之外的多级钻取 |
| 瀑布图（`waterfallChart`） | 增减贡献及累计结果 | 一个有业务顺序的分类和一个可累计的增减指标 | 不把各期余额当作增减额；截断分类后的累计只代表可见部分，不能称为完整总额 |
| 桑基图（`sankeyChart`） | 多层分类间的流向 | 2~4 个有真实对应关系的不同分类字段，按流向排列；一个统一口径的权重指标 | 仅有当前状态不能推导历史流转路径 |
| 双轴图（`dualAxisChart`） | 双量纲分析 | 共用的分类或时间维度，以及主轴、副轴各自的指标 | 如销售额与增长率；明确两轴单位，不用不同刻度造成大小可直接比较的错觉 |
| 排行榜（`rankingChart`） | 排行榜 / TopN | 排名对象、排序指标及方向 | 默认推荐展示 5~10 项；用户指定范围优先 |
| 透视表（`pivotTable`） | 多维交叉统计 | 分别明确行维度、列维度及汇总指标 | 如部门 × 季度支出，不能用普通分类对比代替交叉分析 |
| 漏斗图（`funnelChart`） | 阶段转化 | 有业务顺序的阶段及可比较指标，或各阶段对应的同口径指标 | 先确定阶段顺序与统计对象，避免把当前状态分布称为实际转化率 |
| 仪表盘（`gaugeChart`） | 指标状态或目标达成度 | 一个指标及有业务意义的量程 | 达成率需明确目标和分母；量程不能仅为视觉效果设置 |
| 子弹进度图（`progressChart`） | 实际值与目标值对比 | 对应的实际指标与目标指标 | 实际与目标的单位、对象、时间范围须一致 |
| 中国行政区划地图（`regionMap`） | 中国行政区划统计 | 地区字段与统计指标 | 仅支持中国行政区划；明确省、市、区等统计粒度，不用普通地名文本代替地区字段 |
| 世界定位地图（`worldMap`） | 世界范围定位分布 | 定位字段与统计指标 | 用于世界范围位置分布，不用普通地址文本代替定位字段 |
| 词云图（`wordCloud`） | 文本热点 / 关键词分布 | 一个文本字段与一个指标，不增加第二个分组维度 | 词项大小表达所选指标，不将非计数指标解释为词频 |

方案与工具调用统一使用 MCP `chartType` 的准确枚举（如 `waterfallChart`、`wordCloud`），保持大小写；中文名称仅用于说明。配置时将上述业务口径映射到 MCP Schema 的实际字段；不把本表当作完整参数清单，也不把设计推荐当作硬性必填。不要为补参数而擅自改变统计定义；读写步骤及类型切换的兼容处理仍由执行器负责。

## 三、选型与表达边界

- 先选择能清楚回答业务问题的图表；无法形成明确结论时不为凑数量生成图表，也不为了类型丰富改变统计口径。
- 分类过多时按业务目的采用 TopN、条形图或分类构成图。截取或合并分类须明确展示范围，不能把局部结果解释为总体。
- 占比和堆叠的各部分须能按业务含义组成总体；类别重叠或口径不一致时，不强行计算占比或相加。
- 明确区分当前存量、期间发生量与历史流转，不能仅通过换图表类型改变数据所能证明的业务事实。
