# HAP 记录数据修订规范

## 一、领域边界

- 本领域处理结构修订所需的记录新增、字段回填、确定性转换、跨表结转和旧字段值清理，以及用户明确要求的少量示例数据写入；示例任务不要求先修改结构。
- 工作表、字段、页面、图表等结构增删改属于对应结构执行器；本领域不得调用 DDL 工具。
- 物理删除字段或工作表由结构执行器在核实数据量、依赖和恢复依据后处理。只有历史数据需要保留或迁移时，才在删除前完成必要的数据保留或迁移阶段。
- 本领域不是普通用户的数据录入助手，不接受与应用修订无关的日常记录增删改。

## 二、接口语义

- `get_record_list` 用于按真实字段 ID、筛选条件和分页读取记录。存量记录写入前必须先以同一目标筛选调用 `includeTotalCount: true`、`pageSize: 1`、`pageIndex: 1` 探测数量。
- `batch_update_records` 是同值广播：一组 `fields` 原样应用到全部 `rowIds`，不能用于每行目标值不同的转换。
- `update_record` 是单行局部字段覆盖。多值字段的已提交值是整体替换，不是追加；逐行差异转换只能逐条调用。
- `batch_create_records` 可一次创建多行且每行字段不同，返回 `rowIds`。响应状态不明时，只有存在稳定唯一业务键才能回查并安全判定。
- 所有记录写接口默认可能触发工作流。本领域每次写入都必须显式传 `triggerWorkflow: false`，不得依赖默认值。
- 当前字段写入 Schema 未声明 `null`。禁止猜测用 `null` 清空字段；清空值必须符合实时工具 Schema 和已验证的字段类型语义。

## 三、执行方式

数量阈值统一遵循 `hap-revision-safety` 的记录数据修订规则。

| 行为 | 更新方式 | 风险下限 |
|---|---|---|
| 新功能配套初始记录 | 按稳定业务键查重，仅对缺失项 `batch_create_records` | `low` |
| 明确要求的示例数据新增 | 按执行器与共用示例 Skill 生成，复用纯新增的查重、批量写入和防重流程 | `low`（不涉及其他高危后果） |
| 新字段空值统一初始化 | `batch_update_records` | `low` |
| 覆盖已有字段的同值广播 | `batch_update_records` | `high` |
| 每行目标值不同的确定性转换 | 逐条 `update_record` | `high` |
| 跨表创建并回写关联 | 两个有依赖的阶段：目标表批量创建 → 源表逐条回写 | `high` |
| 已验证清空语义的旧字段批量清理 | `batch_update_records` | `high` |

- 已明确授权数量、身份及字段值的新功能初始记录新增，以及已明确授权数据范围及目标值的新字段空值初始化为 `low`，可使用 `direct`；低风险新增数据处理方案说明连带影响并经用户确认后可使用 `direct`；高风险（`high`）数据操作必须说明连带影响并取得 `confirmed`。
- 超过阈值、无法取得全部真实 `rowId`、网络状态不稳定或预计无法在单次执行上下文内完成时停止自动执行，转为人工或平台批处理方案。
- 超量时建议使用 HAP 工作表全选批量编辑、平台工作流批处理或受控导入工具；不得在对话中高频循环绕过阈值。

## 四、范围冻结与漂移检查

以下冻结要求用于更新存量记录；纯新增使用拟新增清单和业务键查重，不要求取得尚不存在的 rowId。

1. 使用本次实际筛选条件探测目标数量；不得以整表数量替代目标范围，也不得以筛选失败后的无条件查询继续执行。
2. 在首个写调用前分页取得全部目标 `rowId`，去重后数量必须与探测值一致。
3. 多批次写入基于这组冻结 ID 分片，禁止一边更新一边用会因目标值变化而移动分页结果的筛选继续翻页。
4. 获得相应授权后，执行前重新探测。数量、字段结构、映射规则或目标范围漂移时停止写入并重新取得相应授权。
5. 存在持续写入、无法冻结范围或同数量成员替换也可能造成错误时，停止自动执行并转人工处理，不得声称具有事务或快照隔离。

## 五、操作前置条件

### 新功能初始记录

- 只创建本次新功能必要或用户选定的初始记录；表与字段先创建并验证，再执行数据批次，复用前序真实 ID。不扩展成日常业务录入；示例数据按下节处理。
- 执行前明确数量、身份、字段值及重复处理；有业务含义的必填值缺失时先消歧，非必填且不影响目标的值可留空，不猜填日期、数量、人员或状态。
- 依据稳定业务键（可为核实唯一的组合）定向查重，可合并查询；零匹配才创建，唯一匹配且批准值满足时复用，重复匹配或值冲突时停止写入并重新确认，不覆盖已有记录。并发创建无法可靠排除重复时停止自动执行并转人工处理，不声称查询加创建具备原子性。
- 同一父表合并创建缺失项，显式 triggerWorkflow: false；完整成功响应即为依据，不逐条回读。返回真实记录 ID 及其业务键供后续关联；复用记录也返回真实 ID 与依据。
- 状态不明先按业务键回查，无法唯一判定返回 unknown；不得重放成功或未知项，也不得通过自动删除伪造回滚。保留创建清单、业务键和实际结果作为恢复依据。

### 用户明确要求的示例数据

用户在新建表问答中实际选择添加示例，属于已明确要求；复用已建表及真实字段 ID 执行，不重新建表或重复确认低风险授权。按已授权场景生成，字段填值与素材选型遵循 `hap-sample-data-spec`；复用上述纯新增的查重、完整成功响应验证与未知结果防重流程。

### 同值初始化与广播

- 目标字段必须存在、类型可写，全部目标记录使用完全相同的字段值。
- 初始化必须证明目标字段在全部目标记录上为空；覆盖非空历史值时必须读取值分布并在批准计划中说明恢复依据。
- 每批检查 `successfulRowIds` 与 `failedRowIds`，外层成功不代表全部记录成功。

### 逐行差异转换

- 新旧字段必须同时存在，旧字段保持不动，直到新字段逐行验证和整体对账完成。
- 映射必须是确定字典、确定公式、无歧义拆分或唯一匹配。禁止按自然语言语义、相似名称或模型判断猜测目标值。
- 每条记录写后回读目标字段；任一异常立即停止剩余记录并报告已完成范围。

### 跨表结转

- 新表、必要字段和关联方向必须已由前置结构批次创建并验证，所有占位符必须解析为真实 ID。
- 目标表必须有稳定唯一业务键。创建前先查重；响应不明时按该业务键回查，无唯一键不得重试创建。
- 目标记录创建与源表关联回写分为两个阶段：第一阶段只写目标工作表，优先使用 `batch_create_records` 返回的真实 `rowIds` 记录业务键与 ID 的对应关系；只有响应缺少 ID 或状态不明时，才按唯一业务键回查。第二阶段依赖第一阶段结果，解析并核实真实 ID 后只写源工作表。
- 先验证目标记录真实 ID，再执行关联回写。部分成功时保留已创建记录并准确报告，不得自动删除伪造回滚。

### 旧字段数据清理

- 新字段必须完成 100% 对账，全部直接引用已切换，且用户已明确批准清理。
- 根据字段类型使用经过验证的清空表达；当前 Schema 不接受的 `null` 禁止调用。
- 无法确认清空语义时停止自动执行并说明需人工处理；新字段存在异常空值、对账未通过或引用未完全切换时报告失败。两种情况都保留双轨数据，阻断依赖的旧结构清理。

## 六、验证、重试与结果

- 每批根据接口结果验证成功数、失败数和剩余未达目标数；批量结果明确完整成功时不逐条回读，逐行转换、必要业务样本、状态不明或接口结果不完整时仍须回读。最终剩余数必须为零，逐行转换还必须逐条断言。
- 写入超时或状态不明时先回读。更新只重试确认未达到目标的 ID；创建仅在唯一业务键能够证明未创建时重试。
- 恢复依据至少包含目标筛选、冻结数量、字段 ID、原值分布或逐行旧值、目标值和批次结果。无法保存足够恢复依据时不得执行不可逆覆盖。
- 禁止把模型上下文描述成持久执行日志。跨会话、长时间或需要断点续传的迁移转为平台原生批处理或人工方案。
