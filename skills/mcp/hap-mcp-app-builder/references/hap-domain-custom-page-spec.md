# HAP 自定义页面领域规范

本 Skill 说明页面构造、业务组件选择、信息层级与视觉布局，供创建与修改场景共用。工具参数名、类型、必填项、枚举、默认值和字段语义以当前 MCP Server 对应工具的 Schema/description 为准；图表选型与统计口径统一使用 `hap-chart-design-guide`，本 Skill 保留页面专属设计。读取、写入、分批、冲突处理和结果核验由加载本 Skill 的执行器定义。

术语按所属位置区分：**工作表统计图**是工作表「统计」面板中的图表；**自定义页面图表**是自定义页面中的图表组件。两者均可使用工作表作为数据源，不能仅凭 worksheetId 判断归属。

## 一、适用模式与修改安全

### 1.1 何时应用页面构造法则

- **外链页面**：仅挂载真实网址，不属于画布；下文 Dashboard、Workspace、组件、图表与布局规则均不适用。外链页面与画布内的网页嵌入组件不同，不能为挂载整页网址自动搭建组件树。
- **新增画布页面**：按目标用途完整应用 Dashboard 或 Workspace 构造法则。
- **明确要求整体重建页面**：可按对应构造法则重新设计，仅在批准范围内替换原组件。
- **局部修改已有页面**：默认继承现有页面类型、视觉语言、组件节奏与布局；只改受影响部分，不因加载本 Skill 而把整页自动改造成模板。
- 用户明确要求改变画布用途或视觉体系时，才在 Dashboard / Workspace 之间重构；不据此转换画布与外链页面类型。

用户明确的业务与视觉要求优先于默认设计，但须在工具支持范围内实现。下文的组件数量、样式与尺寸用于补全未指定的设计，不要求局部任务补齐整页。统计内容须有真实数据依据，不能为凑数量编造字段或统计口径。

### 1.2 对象与修改范围

- 页面空壳与页面组件内容是不同层次；已有页面身份直接复用上游输入或已确认的事实。
- 页面组件身份、内部统计图身份及数据源身份分别使用，不因数据源相同而合并自定义页面图表与工作表统计图。
- 局部修改保留范围外的组件、配置、身份与布局，不为无关属性变化重建整页或替换图表。页面创建、读取、写入工具选择及结果核验由各执行器负责，本 Skill 不增加工具调用步骤。

### 1.3 页面全局样式与单图样式

- 页面背景、全局图表配色和标题样式用于建立整页统一风格；单个图表的视觉调整仍以该图表为范围，不为局部需求改动全局设置。
- 页面全局颜色可能覆盖图表自身配色；设计时优先满足用户要求的统一风格或单图强调，避免同时设置互相冲突的颜色。已有页面局部修改保留未涉及的全局设置。
- 同数据源组件自动联动与共享筛选组是不同能力；开启自动联动不能替代第 5 节按业务含义设计的筛选控制关系。
- 修改页面背景色时复用有效的当前页面设置，缺失时读取，按当前浅色/深色风格及 MCP Schema 选择 `style.backgroundColor` 预设值；组件或富文本的自定义颜色不适用于整页背景。宽泛风格优化在预设内完成；指定颜色不可用时说明限制和合法选项，不擅自替换颜色或切换风格。

## 二、页面配置与真实 ID

### 2.1 标识与数据来源

- 已有页面、工作表、视图、字段、组件和图表的真实标识只从当前 MCP 响应或明确交接的事实中取得，不凭空编造。新组件需要调用方生成的本地标识时，按工具 Schema 生成并保持引用一致；本地标识不代替服务端真实身份。
- 使用 alias 或字段值时，遵从对应工具 Schema 的支持范围；不要凭名称相似编造 ID。
- 每张图表单独绑定其数据源工作表与字段：`dimension[].field` 必须来自该图表 `worksheetId`（单图接口为 `worksheet_id`）所属表的有效结构；行列维度、指标、排序和筛选中的工作表字段同样按本图数据源核对，系统字段或图表公式按专用契约处理。多图表组装、复制图表或切换数据源时重新核对受影响映射，不能沿用上一张图或关联表的字段 ID。同名字段和两表存在关联都不能证明归属正确；本表缺少所需字段时报告缺口，不为通过校验擅换数据源或统计口径。复用有效结构即可，不要求逐图重复查询。

### 2.2 统计数据源选择规则

统计数据源、聚合口径、时间范围和图表类型按共用的 `hap-chart-design-guide`。页面执行器复用有效的工作表与字段信息，再按第 5 节确定各筛选项实际控制的对象；不能因图表放在同一页面就混用数据源或统计范围。

### 2.3 组件构造与引用

组件类型、必填配置、容器引用、父子层级和 ID 生成方式以对应页面工具的实时 Schema 为准。设计时先确定组件职责及归属；新建或整体重建形成完整组件结构，局部修改保持受影响组件与现有结构的引用一致，不要求重建整棵组件树。不要跨层级引用，也不要将展示内容放入与其职责不符的组件。

## 三、页面生成规范

根据新增/重建页面的目标类型，采用不同的页面组织方式。

### 3.1 Dashboard（仪表盘）

页面按「筛选器 → 分段 + 统计」方式组织，阅读顺序为：筛选器 → 核心指标 → 分析图表。

推荐结构：

```text
filtersGroup（全局数据筛选器，置于最顶部）
section（核心指标）
numberChart × 2~6                            ← KPI 区
section（数据分析）
lineChart / columnChart / barChart / pieChart / rankingChart ...
```

- 新增或整体重建 Dashboard 时，顶部配置 1 个 `filtersGroup`。
- 包含 2~3 个业务化命名的 `section`。
- 同时包含 2~6 个 KPI 与 2~4 个分析图表。
- KPI 位于分析图表之前。
- 局部修改存量 Dashboard 时不强制补齐数量；只保证新增组件与现有结构协调，除非用户明确要求整体优化。

### 3.2 Workspace（工作台）

页面按「顶部引导区 → 快捷入口 → 核心指标 → 业务列表与辅助图表」组织。工作台默认不加全局筛选器；只有明确需要用同一条件联动多个组件时才添加，放在受控组件之前。单个列表沿用视图自身的筛选。

核心组件：

```text
text（使用指南，含业务导引）       ← 顶部引导区，上方不加 section
button（一组 3~6 个快捷按钮）     ← 紧接顶部引导区，无独立 section
view × 2~4                       ← 核心业务列表
```

新增或整体重建 Workspace 时，业务区域默认采用「左侧 View + 右侧上下排列的两张辅助图」组合，并基于真实工作表结构补充以下统计组件。方案只列出 View、未枚举辅助图，不等于明确排除统计；用户或上游方案明确不需要统计时不添加，缺少统计依据时不凑数。局部修订不自动扩展整页：

```text
section × 2~3                    ← 业务化分段标题
numberChart × 2~6                ← KPI 指标卡片区
chart × 2 per view               ← 每个 View 右侧 2 个辅助图表
```

补充规则：

1. 从所有 View 数据源中选择 2~6 个最有业务价值的 KPI，集中放在第一个 Section 下方、业务列表和分析图表之前。
2. 每个 View 右侧搭配 2 个辅助图表，优先选择饼图 + 柱图/条形图；分析维度优先状态/类型字段，其次时间字段、关联字段。
3. View 与右侧两张辅助图直接放在同一父级、共用同一 48 列坐标空间；默认不为右侧图表套 container，即使容器无标题、透明或无外框，也可能保留内边距和独立栅格间距。以业务区起始行 Y 为基准，View 用 `x=0,y=Y,w=32,h=22`，右上图用 `x=32,y=Y,w=16,h=11`，右下图用 `x=32,y=Y+11,w=16,h=11` 作为布局起点。三者共用上方业务 Section，保留各组件自身标题，不额外增加右侧组标题或卡片外框。按同一父级的行高与间距校准两侧顶底边，下一组从实际较低的底边之后开始。用户明确要求容器分组时才保留该结构，并计入容器标题、内边距与内部间距；不能只隐藏标题就认为已经对齐。修复已有对齐问题时，可将仅作右侧装饰包裹的图表移到 View 所在父级；保留图表身份、配置和联动引用，按工具契约先完成迁移再移除空容器，避免级联删除子图表。
4. 先为每个 View 确定配套分析，再一起安排这一组的尺寸与位置；顶部 KPI 不能替代右侧辅助图。仅当用户明确要求通栏、视图内容在分栏宽度下确实无法正常阅读或操作，或缺少有效辅助统计时，该 View 才采用通栏；有价值的配套分析可放在紧邻的下一行，不因视图是日历或看板就自动取消组合。
5. Section 名称结合 View 业务主题和分析维度生成，如「变更审批与风险分析」「重点项目跟进与工时分析」，禁止使用空泛标题。
6. Text 使用指南按业务结构选型：涵盖多阶段流转、多角色分工或并行作业模块时优先采用多场景分栏卡片；仅单一简单步骤或简短规则说明时采用线性列表，详见第 8 节文本组件规则。
7. 局部修改存量 Workspace 时不自动扩展整页；仅在新增页面、整体重建或用户明确要求补齐工作台能力时应用这些默认数量。

## 四、布局指导

推荐尺寸参照 `spec-pages-charts` 的布局规范，数值卡片按图标与对齐方式采用下表中的分档高度，其余组件沿用规范尺寸。位置字段、合法取值与栅格硬约束以页面工具当前 Schema 为准。仅在推荐尺寸造成内容溢出、明显空洞、重叠、越界或无法满足容器与同排对齐时，针对受影响区域调整。局部修订仍遵循第 1.1 节保留未受影响区域的布局，工作台分栏采用第 3.2 节的配套尺寸。

| 组件 | 推荐宽度 | 推荐高度与依据 |
|---|---|---|
| `filtersGroup` | 通栏 `w=48` | `h=5`；仪表盘置顶 `y=0` |
| `section` | 通栏 `w=48` | `h=2` |
| `numberChart` | 2 张一行 `w=24`；3 张一行 `w=16`；4 张一行 `w=12`；5 张一行前 4 张 `w=9`、最后 1 张 `w=12`（补齐 48 列）；6 张一行 `w=8` | 有图标且居中：`h=9`；有图标且左对齐、或无图标：`h=7`，详见第 6.3 节 |
| 分析图表（趋势/分布/对比） | 半宽 `w=24` 或通栏 `w=48`；与 View 搭配时 `w=16` | `h=12`；与 View 搭配时 `h=11` |
| `pivotTable` | 通栏 `w=48` | `h=12` |
| `button` | 通栏 `w=48` | `h=6` |
| `view` | 新增/重建 Workspace 默认 `w=32`，右侧配套辅助图；符合第 3.2 节通栏条件或在非 Workspace 页面独立展示时 `w=48` | `h=22` |
| `text` / `carousel` | 单独展示时通栏 `w=48`。工作台顶部引导区同时展示两者时，线性列表式指南与轮播并排，各 `w=24`；多场景分栏指南放在轮播正下方，两者各 `w=48` | 指南按第 8.2 节估高；轮播独占一行时 `h=10`，并排时与指南等高 |
| `container` | 按承载的子组件和页面分栏计算 | 与同排组件对齐，并容纳子组件（页面设计建议） |

上表数值是页面设计推荐值，不等同于接口默认值或校验限制；容器内按独立坐标空间换算。`spec-pages-charts` 未单列尺寸的组件（如外部页面嵌入）按实际内容、所在区域及工具约束安排，不套用文本高度公式。

设计时优先保证视觉层级、对齐、阅读顺序和相邻组件协调：

| 组件用途 | 布局建议 |
|---|---|
| KPI | 同组对齐、尺寸一致，放在明细分析之前 |
| 分析图表 | 按阅读顺序组织；同排组件保持视觉平衡 |
| 业务列表 | 给主要工作对象更大展示空间 |
| 使用指南与快捷入口 | 靠近页面顶部，便于开始操作 |
| 容器与标签页 | 先确定内容归属，再按对应区域独立规划内部布局 |

### 4.1 尺寸与相邻布局

- 服务端不会因一个组件变宽、变高而自动重排其他组件。布局须同时考虑同排对齐、下方占位、容器内外尺寸、重叠、越界和空洞。
- **48 列整行宽度与分栏高度末位补齐**：计划铺满整行的同排组件总宽度须精确凑满 48 列（最右侧组件满足 `x + w = 48`）；当同排组件数量无法被 48 整除时（如 5 张数值卡片一行：`48 ÷ 5 = 9` 余 `3`），前 $N-1$ 个组件取整数均分宽度（`w=9`），**由该行最后一个组件补齐剩余宽度**（`x=36, w=12`）。同理，在左右分栏组合中（如左侧 1 个高组件、右侧上下叠放多个组件对齐同高），当总高度无法等分时，**由纵向最后一个组件补齐剩余高度**（使右侧底边 `y + h` 与左侧底边精确齐平），严禁在行末或列底留出未对齐的缺口。
- 按页面根级、container 和各 tab 的坐标空间分别计算。尺寸变化或插入组件时，只调整实际受影响的邻接区域，不要求所有组件都修改尺寸；新增组件与现有风格保持协调。

## 五、筛选器组件（filtersGroup）

### 5.1 筛选组设计与联动

- 新增或整体重建 Dashboard 时，按第 3.1 节在顶部配置 1 个 `filtersGroup`，其中可包含多个对分析有用的筛选项；局部修改不强制新增或重组已有筛选器。
- Dashboard 的筛选器是页面级共享入口：同一业务条件只设计一个筛选项，并将它映射到所有确实应受其控制的图表或视图；不要为每张图表各建一份重复筛选器。
- 共享不表示每个筛选项都要控制页面上的全部图表。只映射到业务含义一致且应受该条件影响的对象；例如赞助状态筛选控制赞助相关图表，展位状态筛选控制展位相关图表。不同业务含义或不兼容的字段应使用不同筛选项，不能为了覆盖更多图表而混为一个条件。
- 页面执行器根据图表用途、数据源及工作表结构确定每个筛选项的联动对象；同一筛选项联动不同工作表时，逐个使用目标图表或视图对应工作表中的真实兼容字段。字段名称相同不代表字段或筛选语义相同。只有业务含义或兼容关系无法可靠判断时才报告缺口，不猜测字段或改变业务定义；具体映射参数遵从 MCP Schema。
- 各映射字段须与筛选语义兼容；已有目标对象、字段类型和筛选选项必须来自真实页面及工作表信息，新建组件的引用按第 2.1 节保持一致。
- 新增筛选器优先使用页面 MCP Schema 声明的语义配置，单个动态日期默认值用字符串，如 `"defaultValue": "thisMonth"`；已有筛选器只修改获批属性，并按工具说明保留扩展设置。
- 当 filtersGroup 已承担时间范围筛选时，检查关联图表是否还有默认时间窗口，避免两个时间条件叠加缩窄数据；图表自身 `timeRange: "all"` 表示不设图表级固定时间窗口（由 `filtersGroup` 动态控制时间范围），属于正确的无双重限制状态，严禁将 `timeRange: "all"` 误判为“未跟随筛选”而改为 `thisQuarter`/`thisMonth` 等固定范围。用户要求保留的固定业务时间范围不能擅自移除，具体时间参数按图表 MCP Schema 处理。

## 六、图表组件与选型

### 6.1 图表选型与配置依据

图表类型映射、统计口径及选型建议统一使用 `hap-chart-design-guide`，本 Skill 不再维护第二份选型表。该指南与本 Skill 由页面 Build 和修订执行器一并加载；工具参数以实时 MCP Schema 为准。

### 6.2 页面图表的搭配原则

- 新增或整体重建页面时，围绕不同分析目的组织 KPI、趋势、对比、构成等图表，避免整页只重复一种分析；不能为了类型丰富凑图或改变业务口径。局部修改不要求重配全页。
- 组件尺寸、排列与容器内坐标遵循第 4 节；Workspace 的业务列表与辅助图配比遵循第 3.2 节。
- 全局配色与单图样式遵循第 1.3 节，页面共享筛选及时间条件遵循第 5 节，数值卡片的图标、结构与高度遵循第 6.3 节。

### 6.3 数值卡片的默认样式

以下默认用于新建、整体重建页面，以及用户明确要求重新设计样式的数值卡片；用户指定样式优先，局部修改已有页面时按第 1.1 节继承现有视觉风格。

先在同一布局区域内按可用宽度确定指标组的分行，再按行数与每行卡片数量选择样式。同组统一使用一种样式；末行不足一整行时，按该组最多一行的卡片数量判断。不同业务分组分别判断，不把整页上下排列的多个指标组当作同组多行。每行数量包括同排仪表盘等指标卡片，但下列规则只改变数值卡片的样式，其他类型保留自身图形结构。

**先选样式：**

| 指标组布局 | 图标 | 推荐对齐 |
|---|---|---|
| 每行不超过 4 张，不论单行或多行 | 有图标 | 左对齐：`layout.align: "left"` |
| 单行，超过 4 张 | 有图标 | 居中：`layout.align: "center"` |
| 多行，每行超过 4 张（末行不足按上述规则判断） | 无图标及图标占位 | 居中：`layout.align: "center"` |

**再按图标与对齐方式定高度：**

| 样式 | 内部结构 | 组件高度 |
|---|---|---|
| 无图标，默认居中 | 仅保留标题、数值及必要单位 | `h=7` |
| 有图标，居中 | 图标在上，标题和数值在下 | `h=9` |
| 有图标，左对齐 | 图标在左，标题和数值在右 | `h=7` |

`h` 是页面组件的栅格高度，不是图表内部样式字段。新建时同时设置图标、对齐与高度；修改图标显示或对齐方式时，按样式表同步更新高度及受影响的相邻布局。只有“有图标且居中”使用 `h=9`，不能将无图标居中也设为 `h=9`。用户明确指定样式或高度时优先遵从；未涉及样式或尺寸的局部修改保留原布局。

- **数值卡片图标铁律**：数值卡片的图标值（`icon.icon`）必须带 `sys_` 前缀，且必须从 `hap-icon-palette` 精选白名单中选取贴合指标业务语义的 `fileName`（如 `sys_4_1_calendar` 日历、`sys_4_2_clock` 时钟、`sys_6_1_user_group` 群体、`sys_7_1_truck` 调度），**严禁凭空捏造非法 key，严禁无脑使用默认示例 `3_1_coins`**。
- **白底与业务图标**：默认使用白色卡片。需要图标时，选择能表达统计内容的有效图标，同类指标保持图标风格一致；标题与数值始终是阅读重点。
- **主题与语义配色**：以已知应用主题色为基础，结合指标含义选择图标、图标底色及数值强调色；一般总量沿用主题色，完成或达成可用绿色，待处理可用橙色，异常或风险可用红色。同一含义保持同色，不为区分卡片而随意使用警示色。标题和数值保证足够对比度；主题色未知时沿用页面已知配色或平台默认色，不猜测应用主题。
- **文字大小**：默认 `value.fontSize: 28`，用户指定优先；更新时省略该字段保留原值，恢复默认须显式传 `28`。
- **排版与样式一并确定**：页面执行器先按可用宽度确定分行，再选择内部结构、图标及对应推荐高度，计算各行位置并确定配色与文字大小。新建组件时一并写入样式，局部修订按已有对象与工具边界更新。尺寸需容纳标题、数值及单位，同组数值卡片保持等高，并同步处理受影响的相邻布局。
- **参数路径**：上述样式字段位于单图的 `config.numberCard` 或页面组件的 `config.config.numberCard`，以实时 MCP Schema 为准。

## 七、按钮与轮播组件的设计

- 同一组相关快捷操作集中呈现，名称直接描述用户将完成的动作；目标对象必须来自真实上下文。不要为每个按钮重复创建孤立组件。
- 按钮项使用与动作语义一致的图标，沿用有效映射：新建记录用 `add`，打开视图用 `view_eye`，打开自定义页面用 `custom_navigation`，打开外部链接用 `launch`。同一页面中相同动作保持图标一致，避免仅为装饰更换含义。
- 按钮按用户实际操作频率和流程顺序排列；主要动作优先，低频辅助动作靠后，避免把互不相关的操作塞进同一组。
- **按钮主题色与外观样式**：
  - 按钮配色（`buttons[].color`）必须**以当前应用主题色（`appColor`）为主基调**，严禁无视应用主题色把整组按钮机械刷成固定默认蓝（如 `#2196f3`）。核心主动作优先使用应用主题色；包含异常上报/告警、跨角色维保/协同、日常排期/查看等不同性质动作时，可结合语义搭配警示橙红（`#ea580c`）、协同蓝（`#2563eb`）、次级绿（`#16a34a`）或主题同色系深浅色阶形成视觉层次；纯同类顺承建单动作则围绕应用主题色及同色系深浅色保持统一。
  - 工作台快捷入口的 `config.buttonStyle` 优先推荐圆角胶囊样式（`"round"`）或与页面卡片风格协调的实心样式（`"solid"`）。
- 轮播使用与展示需求匹配的数据源和素材字段。工作台上，面向整页的轮播放在顶部引导区；服务于某个业务区的轮播紧邻该区。
- 两类组件的动作、目标字段及必填参数以页面工具 Schema 为准，不在本 Skill 重复参数枚举。

## 八、文本与视觉样式

本节的 HTML 标签与 CSS 示例用于文本组件的富文本排版；外部页面嵌入组件按实时页面工具 Schema 配置。以下规则用于组织可读内容，不替代工具参数说明。

### 8.1 排版形态与适用场景

按业务结构选择排版形态，避免千篇一律使用单一列表或把多步流程揉成一段长句：

- **多场景分栏卡片（多阶段流转 / 多角色协同 / 并行模块，工作台优先推荐）**：当工作台涵盖 2~4 个作业阶段（如「1. 调度与派单 → 2. 接单与完工 → 3. 异常与维保」）、多角色职责分工或多个并行功能模块时，优先使用 2~4 列 Grid 分栏卡片（`display:grid;grid-template-columns:repeat(3,1fr);gap:14px;margin-top:12px`），严禁将多环节流程偷懒堆砌成单段 `①... ②... ③...` 纯文本。子卡片推荐使用**圆角白底 + 左侧 4px 语义色竖条**的精致样式（`background:#ffffff;border-radius:10px;padding:14px 16px;border-left:4px solid <语义色>;box-shadow:0 2px 6px rgba(0,0,0,0.04)`；深色底板下可用半透明亮底 `rgba(255,255,255,0.08)`）：首张主流程卡片左边框优先用**当前应用主题色**，其余分栏按环节语义搭配蓝 `#2563eb`、绿 `#16a34a`、橙 `#ea580c` 或紫 `#7c3aed`，卡片内顶部放加粗步骤小标题（`font-size:15px;font-weight:600;color:#1e293b;margin-bottom:6px`），下方配 2~3 行精炼操作指引（`font-size:13px;line-height:1.6;color:#475569`）。
- **线性列表式指引（单一简单路径 / 简短规则说明）**：仅在单一角色按简单顺序执行 2~3 步操作、或只需交代简短注意事项而无需分栏展开时，采用 `<h4>` 标题 + `<p>` 说明 + `<ul>` 列表。
- **重点提示区块与主题色呼应**：关键业务规则或提示区块应结合当前应用主题色（或按需采用深色背景）设计同色系柔和浅底、微渐变或主题色强调边框，严禁脱离应用主题色生硬套用固定淡蓝（`#f0f9ff`）或淡黄背景。

### 8.2 内容高度估算

- 基础高度 `h=5`，用于外层 padding 和基础间距。
- 主标题 +1；每行说明段落 +1；每个列表项 +1，明显折行时 +2。
- 每行 Grid 卡片 +4；卡片内说明达到两行或更多时 +5。
- 示例：标题 1 + 说明 1 + 3 个列表项 3 → `h=10`；标题 1 + 一行 Grid 4 → `h=10`。
- 目标是避免高度过大造成留白，也避免高度过小出现滚动条。

### 8.3 文本内容与组件外观样式

- **组件透明去白底**：当富文本自带外层背景色、圆角底板或分栏卡片时，必须将 `text` 组件的顶层 `appearance` 设为 `"transparent"`，去掉组件外部默认的白色卡片底框，避免出现“外部白底方框套内部圆角色块”的双层割裂感与右侧多余滚动条。
- **外层容器与主题配色**：外层 `<div>` 设置 `height:100%;box-sizing:border-box;overflow:hidden;border-radius:12px;padding:20px 24px`，内容自然置顶。背景与标题色必须结合当前应用主题色（`appColor`）或页面风格设计：可使用与应用主题色同色系的柔和浅色/微渐变背景配主题深色标题与深色正文，或按需使用深色背景（如 `#1e293b`、应用主题深色系底板）配浅色文字。
- 每个文本标签显式写行内 `color` 与 `font-size`，防止全局 CSS 覆盖。
- `<h4>` 建议 `font-size:17px;font-weight:600;margin-top:0`；`<p>/<li>` 建议 `font-size:14px;line-height:1.8;margin-bottom:0`。
- 可用 emoji、`<strong>` 或高亮 `<span>` 强调关键词，但不堆砌装饰。

## 九、其他组件

使用 section、view、tab、container 等组件时，按实时 MCP Schema 提供组件专属配置。先确认其在页面中的职责、归属和与其他组件的关系，再构造参数；本 Skill 不重复字段定义和枚举。

## 十、提交前自检

1. 新增/重建页面是否应用了正确的 Dashboard 或 Workspace 构造法则？Workspace 中每个 View 是否有右侧配套分析，或有符合第 3.2 节的通栏依据？顶部 KPI 不能代替配套分析。局部修改是否保留未受影响区域？
2. 已有对象标识是否有真实来源？新组件本地标识是否按工具规则生成并保持引用一致？
3. 组件及引用是否完整，是否保留修改范围外的配置和真实身份？
4. 组件尺寸与位置是否形成清晰阅读顺序，是否影响邻接区域或造成明显留白？**宽度与高度不能等分时是否已由最后一个组件补齐**（同排铺满整行的组件总宽是否精确凑满 48 列、最后一个组件满足 `x + w = 48`；左右分栏叠放的组件总高是否与邻列顶底边精确齐平、纵向最后一个组件补齐剩余高度）？数值卡片的分行、结构、高度与统计值文字大小是否符合第 6.3 节或用户明确要求？
5. 是否逐图核对数据源与工作表字段归属，未混入其他图表或关联表的字段 ID？图表类型、维度和指标是否匹配？地图是否有对应的地区/定位字段，类型专属参数是否适用？
6. 快捷操作是否清晰、目标对象是否来自真实上下文？
7. filtersGroup 是否只联动预期对象、使用语义匹配的目标字段，并保留未改的现有配置？
8. 技术字段和参数细节是否直接依据当前 MCP Schema，没有在 Skill 中另造字段或枚举？
