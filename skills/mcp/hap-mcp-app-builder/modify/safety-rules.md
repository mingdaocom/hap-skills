# Modify 安全底线与风险执行协议

> 同源基准：`skills/hap-revision-safety` + `skills/hap-revision-execution` + `skills/hap-revision-backup`

本文件定义修改已有 HAP 应用不可绕过的永久安全底线。命中阻断条件时必须立即停止受影响写入并向用户如实说明。

---

## 一、 二元风险分级与确认决策（`low` vs `high`）

所有写入必须追溯至用户明确要求（`requested`）或实现目标不可缺少的连带修改（`required_linked`）；推荐项（`recommended`）未经用户明确选中严禁执行。执行风险按客观业务后果严格分为两档：

### 1. 常规低风险（`low` ➔ 范围明确时直接连续执行）
未命中下方 6 类高危后果且无未决业务歧义的操作均为 `low`，用户当前明确指令本身即构成有效授权，同目标的 `required_linked` 低风险配套（如新表默认视图翻新、导航合理落位、已选定非系统业务角色的最小非敏感权限）须同轮一气呵成完成，**不逐批弹窗要求二次确认**：
- 应用/工作表/字段/视图/页面/图表/AI 助手/打印模板的常规新增与属性、布局、样式、排序修改；
- 无存量数据空表（本次新建表，或经无筛选 `get_record_list(includeTotalCount: true, pageSize: 1, pageIndex: 1)` 证实整表 `totalCount == 0` 的已有表）的常规结构调整，以及仅回写本表单条记录状态/时间的配套工作流；
- 不含高危写入的工作流草稿创建与修改（`publish: false`），以及已明确收件人、签名、有限频次且不改写业务记录的单条记录通知流发布；
- 明确启用或关闭工作表公开表单（不含刷新公开链接或重置字段）、明确关闭外部门户或按已确认受众常规启用门户；
- 符合下方第 二 节「14 类删除/关闭直通条件」的明确删除或停用操作；
- 安全数量上限内且身份/范围明确的新功能初始记录、新字段空值同值初始化，以及用户明确要求的少量示例数据新增。

### 2. 客观高风险（`high` 或必须确认场景 ➔ 零写入展示方案，取得明确确认后执行）
凡命中以下 **6 类客观高危后果**，或涉及 **`allowExistingDraft: true`（合并发布任务外既有草稿）**、**需 AI 决定拆分/合并/流转替换的既有模块重构**、**刷新公开表单链接使旧链接失效** 时，无论用户原话多简短明确，均必须先零写入展示准确对象、数据/权限影响与可恢复性，等待用户确认：
1. **高危结构/角色删除**：删除非空工作表（`totalCount > 0`）、删除关联记录（`Relation`）或子表（`SubTable`）字段、删除含成员配置的角色，以及直通范围外的高危连带删除；
2. **存量业务数据改写与自动写数流程上线**：覆盖非空历史记录值、逐行差异转换、跨表结转、旧字段值清理、大批量记录更新；或启用/发布（含修改已启用）会自动新增、修改、删除业务记录的工作流（上述 `totalCount == 0` 空表单条状态回写例外除外）；
3. **权限批量收缩或敏感数据外放**：批量收缩权限（含批量移除成员致其失去唯一访问路径）、角色合并，或向外部/全员/未授权范围放开他人敏感数据（含关闭 AI 助手权限检查、扩大公开分享/导出范围、打印模板开启公开记录链接或降低防篡改保护）；
4. **关键业务防线削弱**：削弱关键审批节点、关闭工作流安全校验、改变核心业务流转路径、取消 AI 助手写操作确认；
5. **外部批量群发**：向存量名单批量外发短信/邮件、收件范围不明的对外发送或无限制高频广播；
6. **阻断现有门户登录**：因注册/登录认证方式变更导致现有外部用户无法登录（用户明确要求关闭门户本身除外）。

> **确认绑定原则**：一次确认覆盖该方案内的全部依赖批次；但若用户在确认回复中追加、修改了未评估的新范围，或执行前发现状态漂移扩大了危险影响，原确认失效，须对新增影响补充确认。

## 二、 14 类删除与关闭轻量直通条件

当用户明确要求删除/关闭、目标在当前应用内唯一定位、完成下表最小检查且无独立高危影响时，按 `low` 直接执行（不全应用扫描全部工作流或外部系统，也不擅自用隐藏代替删除）：

| 对象类别 | 最小核查条件与执行边界 |
|---|---|
| **1. 工作表已保存筛选器** | 核实所属表与 `filterId`，仅删筛选配置，不查匹配记录。 |
| **2. 常规及本表计算字段** | 含普通、公式、汇总、他表字段、自动编号；**排除系统字段、当前标题字段、`Relation` 和 `SubTable`**。用 `get_worksheet_structure` 核实非标题且无本表其他字段默认值/公式依赖（有普通表内依赖先询问处置；标题字段须先切换新标题再删）；支持字段回收站恢复，不查记录数或非空值数。 |
| **3. 普通视图** | 确保删除后本表**至少保留 1 个可用视图**；仅处理已知页面内嵌视图引用。 |
| **4. 打印模板** | 核实所属工作表与 `templateId`（含 cloud 模板删除），不查历史打印记录。 |
| **5. 自定义页面** | 核实页面身份，仅删页面自身，绝不删除其引用的工作表或记录数据源。 |
| **6. 统计图表** | 核实归属（页面组件补丁移除 vs 工作表 `delete_chart`），不删源表与源数据；页面内删图同批清理引用它的 `filtersGroup` 映射。 |
| **7. AI 智能助手** | 核实 `chatbotId`，仅删助手本身，不删其绑定的工作表或知识库。 |
| **8. 表单业务规则** | 核实 `ruleId`；停用（`enabled: false`）须先读完整规则配置以保留条件和动作。 |
| **9. 自定义动作** | 核实动作身份；删除动作会连带删除关联工作流（须在用户删除意图内）。 |
| **10. 指定工作流** | 核实当前应用目标流启用/草稿状态，确认无未批准草稿且非核心审批主干；动作关联流不单独调 `delete_process`。 |
| **11. 物理索引** | `get_worksheet_index_list` 返回 `canDelete=true`；唯一索引删除后说明不再强制唯一。 |
| **12. 空角色** | 非系统/非受保护自定义角色，且用户、部门、部门树、职位、组织角色**五类成员配置均为空**。 |
| **13. 导航分组** | 保留全部应用项：二级分组回落父级；唯一一级分组清空名称；其他非空一级分组须有明确或唯一承接分组（多候选先询问）。 |
| **14. 空工作表** | 经无筛选 `get_record_list(includeTotalCount: true, pageSize: 1, pageIndex: 1)` 确认整表 `totalCount == 0`，且已处理已知跨表关联依赖。 |

## 三、 备份策略、最小写入与保护红线

1. **事前备份探测与提问卡片确认（对齐 `hap-revision-backup`）**：
   - **豁免范围**：纯展示文案（名称/备注/说明/提示）、局部图标/配色/视觉样式、应用项导航 `displayType` 显隐、视图/图表/分组/角色纯显示顺序重排及普通新增打印模板免备份，直接执行，**严禁在修改完成后的结果汇报中附加“重要变更前建议先创建应用备份”等事后口号**；
   - **能力探测与免问条件**：本会话首次执行非豁免实质修改前，先调用 `get_app_backup_list(appId)` 检查：① 若返回 `50013`（`reasonCode: "backup_version_unsupported"` 组织版本不支持备份，或 `"backup_access_denied"` 无当前应用管理权限），默认静默省略备份提问直接继续获准修改（仅当用户主动要求备份时才如实告知版本不支持或无管理权限）；② 若列表显示 **5 分钟内已有完成的备份**，或本会话用户已作过备份选择，直接复用不再提问；
   - **事前提问确认与自动备份**：当支持备份且 5 分钟内无备份、本会话尚未选择时，**必须在执行修改写入前**通过宿主提问工具发起单选确认（选项依次为 `"(Recommended) 先备份，再修改"` 与 `"不备份，直接修改"`，说明仅备份应用结构不含记录数据，备份配额满时将自动替换最早备份；若本轮需询问业务消歧或确认 `high` 高危方案，合并在同一轮提问中）。用户选“先备份，再修改”后调用 `create_app_backup(appId)` 完成备份再执行修改；整个会话仅确认一次。
2. **真实标识与全量覆盖保护**：
   - 所有 `appId`、`worksheetId`、字段 `id`/`alias`、`viewId`、`roleId`、`processId` 必须来自当前环境实时读取或前序成功回执，严禁猜测或拼接；
   - 增量接口只传批准差异；**全量覆盖或数组整体替换接口**（如 `update_custom_page`、`update_public_form_settings`、角色的 `globalPermissions`/单表权限数组、视图按钮数组、业务规则更新）必须基于最新完整有效对象合并修改，**读取结果含截断标记（truncated）或残缺时严禁覆盖写入**；
   - 系统预设角色、默认外部门户角色禁止修改或删除；移除角色成员必须按原加入粒度（个人/部门/部门树/职位/组织角色）操作。

## 四、 记录数据修订硬约束

1. **DDL 与 DML 分批**：先完成结构变更并验证真实字段 ID，再执行数据批次；所有修订型记录写入**必须显式传 `triggerWorkflow: false`**。
2. **安全行数上限（超限必须转平台原生批处理或人工导入，严禁循环绕过）**：
   - 纯新增真实初始记录：**≤ 20 条**（须按稳定唯一业务键查重，零匹配才创建）；
   - 用户明确要求的示例数据：每张目标表本次累计 **≤ 20 条**（明细子表按整张子表合计 ≤ 20 条，未指定数量时默认每表 3～5 条）；
   - 新字段空值同值初始化 / 已确认同值广播 / 旧字段清理：单任务 **≤ 5,000 行**，单批 `batch_update_records` **≤ 1,000 行**；
   - 逐行差异转换 / 跨表结转：**≤ 20 行**（跨表结转须拆为“目标表按唯一键创建拿 `rowIds` → 源表关联字段回写”两步）。
3. **范围探测与真实 `rowId` 冻结**：更新存量记录前必须用实际筛选调 `get_record_list(includeTotalCount: true, pageSize: 1, pageIndex: 1)` 核对数量；首次写入前分页拉取并冻结去重全部目标 `rowId`，再复核一次 `totalCount` 无并发漂移后方可分批写入，严禁边改筛选字段边翻页取数。

## 五、 效率优先验证与异常防重纪律

- **按需最小验证**：增量写入工具返回明确同步业务成功及完整目标证据时直接记账收口，不机械重复回读整表；全量覆盖保护、数组替换、数据迁移对账、布局重排、部分失败或结果未知时，集中做一次最小充分回读。
- **结果未知先回读，严禁盲目重放**：遇到超时、断流，或工具报 `structuredContent / outputSchema` 返回契约校验失败时（**返回校验报错不代表服务端未写入！**），第一动作必须是定向回读线上真实状态；已生效则直接收口，确认未生效且原因明确可修时按 [宿主适配](../HOST_ADAPTER.md) 纠正并继续，无法判定是否生效时如实报告 `unknown` 并停止依赖步骤。
