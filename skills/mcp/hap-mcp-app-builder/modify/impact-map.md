# HAP 已有应用修改影响地图

> 同源基准：`skills/hap-revision-impact-map`（本地内联适配版）

## 一、 用途与阅读方式

本文件用于主 Agent 在修改已有 HAP 应用时识别：

1. 用户要改变什么对象；
2. 修改前必须核实哪些一层直接依赖；
3. 哪些连带变化属于完成目标必需（`required_linked`），哪些仅属建议（`recommended`）；
4. 跨领域操作按什么固定顺序执行；
5. 哪些关键事实缺失时必须停止并向用户消歧。

风险分级（`low` / `high`）及删除/关闭直通规则统一由 `./safety-rules.md` 维护；自动化与人工能力边界由 `./execution-boundaries.md` 维护；各领域具体读写方法与工具选型见 `./modify_guide.md` 及对应 `../references/hap-domain-*-spec.md`。

## 二、 统一分类与交互原则

| 分类 | 含义 | 处理原则 |
|---|---|---|
| `requested` | 用户明确要求达到的目标状态 | 在能力边界、事实和授权满足时执行 |
| `required_linked` | 不完成就无法实现或验证已明确目标的必要连带变化 | 纳入本次执行范围并说明依赖关系；必要事实缺失时先澄清 |
| `recommended` | 有直接业务价值但非完成目标所必需 | 仅向用户提出具体选项建议；用户实际选择后才执行，跳过或拒绝则不执行且不算缺项 |
| `no_change` | 实时状态已经满足目标 | 保持零写入并给出实时读取依据 |
| `unresolved` | 当前事实、目标身份或依赖无法确认 | 不得假设无影响；按对应行的停止条件处理 |

### 1. 配套角色授权选择规则
- **询问触发条件**：新建工作表、业务视图、自定义页面或 AI 助手时，若用户原请求或当前会话有效选择尚未明确角色授权范围，先基于 `get_role_list` 的真实非系统业务角色向用户推荐询问一次（优先放入宿主提问工具卡片并按[宿主适配](../HOST_ADAPTER.md)表达多选，供用户直接勾选业务角色，同时提供“仅管理员可见”选项；明确为管理员专用或纯局部修改不涉及受众时不追问）。
- **分类转换**：尚未选定的角色授权属于 `recommended`；用户明确要求或实际选定后，为该受众实现目标所需的最小权限转为 `required_linked`（已有权限已覆盖目标访问时记为 `no_change`，不重复写入或扩大数据范围）。
- **跳过处理**：用户跳过、拒绝或暂不授权时，不新增角色授权、不撤销既有权限，也不据此声称“仅管理员可见”，如实说明本次未新增角色授权即可。

### 2. 新增业务功能的配套与示例数据规则
- **交付缺口识别**：新建或整体设计业务功能时，一次性检查操作入口、状态结果、启用所需的真实基准初始记录及后续自动化流转：
  - 不补就无法完成目标且方案明确的归为 `required_linked`；业务政策或人员范围有实质歧义时先向用户消歧；
  - 有直接使用价值但非必需的视图、看板或独立自动化归为 `recommended` 供用户选择。
- **初始记录与示例数据区分**：
  - 功能运行必需或需求中已给出明确参数的**真实基准初始记录**纳入 `required_linked`（按 `./safety-rules.md` 查重落库）；
  - 尚未发生的业务结果记录保持为空，不为完整性编造；
  - **演示/测试示例数据**仅在用户明确要求，或在多表关联/配套视图图表需数据体验且建表无其他阻塞澄清时，于建表完成后提供一次可选询问（每表上限见 `./safety-rules.md`，拒绝或跳过即止，不为补关联向未授权表造数据）。

## 三、 应用与导航

| 变化 | 修改前必查的直接依赖 | 连带分类 | 领域与执行顺序 | 无法确认时 |
|---|---|---|---|---|
| 修改应用名称、说明、图标或颜色 | 当前应用基础信息 | 无额外连带；未要求属性保持不变 | `app_navigation` | 目标应用无法唯一确定时阻断 |
| 修改单个或多个应用项导航名称/图标/显示模式/备注/用户说明 | 真实应用项 ID、用途与当前必要属性 | 保留未改属性；区分页面/助手的导航名称与实体名称 | 工作表、页面、助手统一走 `app_navigation` (`update_app_items`) | 对象指代不明时消歧 |
| 新建、重命名或调整导航分组 | 当前完整分组树、同级名称和顺序 | 受影响的精确排序为 `required_linked` | `app_navigation` | 分组层级或同级项不完整时阻断 |
| 删除导航分组 | 分组层级、`items`/`childSections` 与可选其他一级分组 | 保留所有应用项；多候选承接去向先询问用户，选定后直接执行 | `app_navigation`（参数契约见 `../references/hap-domain-app-spec.md`） | 非空一级分组存在多个候选承接分组且未选定时询问 |
| 调整导航项顺序 | 目标分组及组内全部应用项真实 ID | 保持其他项相对顺序为 `required_linked` | `app_navigation` | 目标项、分组归属或现有顺序无法核实时阻断 |
| 移动或隐藏入口 | 目标项、原/目标分组、角色可见性、替代访问路径 | 保持必要访问路径为 `required_linked`；备用入口为 `recommended` | 先处理对象归属与 `app_navigation`；权限变化另接 `role_permission` | 唯一入口或受影响角色无法确认时阻断 |

## 四、 工作表、字段、业务规则与索引

| 变化 | 修改前必查的直接依赖 | 连带分类 | 领域与执行顺序 | 无法确认时 |
|---|---|---|---|---|
| 新建工作表 | 目标分组及组内顺序、表名/alias 唯一性、有效角色列表（供推荐询问） | 默认视图与目标必需表单规则为 `required_linked`；角色授权按选择规则处理；组内导航定位为 `required_linked`（同组自定义页面在前、工作表在后，主表在前、明细子表紧随其后；默认追加末尾已满足顺序时免调排序） | `worksheet(含规则/索引) → (view_action) → (app_navigation) → (role_permission)` | 父分组、核心字段或必要数据源不明时阻断消歧 |
| 修改工作表普通属性 | 当前工作表必要属性 | 保留未批准属性为 `required_linked` | `worksheet` | 目标工作表无法唯一定位时停止 |
| 删除工作表 | 真实目标、整表准确记录数（`totalCount`）及已知具体引用 | 空表按 `./safety-rules.md` 直通；非空表按 `high` 确认，不固定追加导航或权限清理 | 已知必要前置依赖处理 → `worksheet` 删除 | 空表证据缺失先补查；已知依赖未决先处理 |
| 新增普通字段 | 当前字段集合、alias 唯一性、表单布局 | 按业务语义就近排入表单布局为 `required_linked`；加入特定视图展示为 `recommended` | `worksheet`；明确要求视图展示时接 `view_action` | 字段身份或布局无法核实时阻断 |
| 新增敏感字段 | 普通字段依赖 + 目标角色字段权限 | 限制不应访问角色为 `required_linked` | `worksheet → role_permission` | 敏感范围或目标角色不明时阻断 |
| 修改字段名称、说明或展示属性 | 目标字段最新配置与布局 | 保留类型、alias、校验等未批准属性为 `required_linked` | `worksheet` | 必要原配置缺失时补读 `get_worksheet_field` |
| 修改字段类型、稳定 alias 或关系目标 | 视图、规则、动作、页面、图表、流程、权限与历史数据 | 新结构、兼容引用、数据迁移、最终引用切换和旧结构清理均为 `required_linked` | 新结构 → 兼容引用 → `record_data` 迁移对账 → 切换引用 → 清理旧结构 | 无安全原地接口且迁移方案未确认时阻断 |
| 新增 Relation 关联字段 | 目标表、方向（单向/双向）、布局 | 完成业务目标所需的反向关系为 `required_linked`；Lookup/Rollup 按目标判断 | `worksheet` | 目标表或关系方向不明时阻断 |
| 新增 SubTable 明细子表 | 从属子表（必须隐藏 `displayType: 2`）、主表布局、汇总需求 | 标准 4 步闭环均为 `required_linked`：① 建隐藏子表；② 主表加 `SubTable`；③ 配齐 `showFields`；④ 主表配 `Rollup` 汇总 | `worksheet` 顺序闭环（先子表拿真 ID，后主表挂载） | 主表、子表字段或汇总关系不明时阻断 |
| 从属子表新增字段 | 子表字段集合、主表对应 `SubTable` 字段及其 `showFields` | **主表 `SubTable` 的 `showFields` 同步补齐该新字段为 `required_linked` 强制连带**；度量字段按需检查主表 `Rollup` | `worksheet` 顺序完成子表加字段与主表 `showFields` 更新 | 主表对应 `SubTable` 控件未定位时阻断 |
| 删除字段 | 真实目标、字段类型、是否标题字段、本表其他字段默认值/公式/计算依赖（普通字段不查记录数） | 未明确的本表公式/默认值引用处置先询问用户；标题字段须先切换新标题再删 | `worksheet` 先解除本表引用/切换标题，再删除字段 | 前置引用调整失败时停止删除；关联/子表字段按 `high` 确认 |
| 修改工作表设置 / 工具栏筛选器 | 当前对应设置或 `worksheet_filter` 详情 | 保留未修改分组或筛选项为 `required_linked` | `worksheet` | 覆盖型设置读取不完整时停止写入 |
| 新建、修改、停用或删除表单业务规则 | 目标字段、条件树、动作与规则身份（停用需完整规则配置） | 停用仅改 `enabled: false` 并保留全部条件与动作为 `required_linked` | 字段就绪后执行 `worksheet` 规则操作 | 缺完整规则配置时先读 `get_business_rule_detail` |
| 新建、改名或删除物理索引 | 可索引字段、现有索引、`canDelete` 状态与唯一性冲突 | 唯一索引存量重复值/空值检查为 `required_linked`；仅改名走 `rename_worksheet_index` | `worksheet` | 唯一索引存量冲突或 `canDelete=false` 时阻断 |

| 启停、隐藏入口或删除自定义动作 | 真实动作身份；视图局部隐藏需该视图按钮列表 | 删除自定义动作会连带删除其关联工作流（严禁单独调 `delete_process` 删动作流） | `view_action` | 连带删除影响未授权时先确认 |

## 八、 跨领域固定依赖顺序速查

1. **新建工作表完整交付**：`worksheet(建表+规则+索引) → view_action(原地翻新默认视图+建业务视图/动作) → app_navigation(仅默认末尾顺序不满足时重排) → role_permission(已选定角色时合并表/视图/动作权限)`。
2. **新建画布页面完整交付**：`custom_page(建空壳+填组件+summary布局校正) → app_navigation(同组页面置顶于工作表前) → role_permission(已选定角色时赋权)`。
3. **新建 AI 助手完整交付**：`chatbot(建助手+ai_agent节点绑定资源并按需发布) → (app_navigation) → (role_permission)`。
4. **字段/工作表非兼容替换**：`创建新结构 → 兼容新旧引用 → record_data 迁移并100%对账 → 切换全部直接引用 → 验证 → 清理旧数据与旧结构`。

前序步骤未取得明确成功与真实对象 ID 时，严禁带着占位符继续执行依赖它的后续步骤；局部成功时如实保留已建对象并汇报剩余缺口，严禁擅自删除已建对象伪造回滚。
